#120轻量/通信续接在原测试文件核验：256窗口、权威周期尾部校正、无记录I/O、GUI/headless
选择和完整留证兼容；真实动态跨段使用原整数Trunc包络及独立物理重放oracle，不能逐位比较
两次独立随机运行或随意扩大误差。真实三条TCP/mTLS链路核验选项及失败关闭；重叠commit
覆盖先发两方、共用deadline、两方发送/ACK错误、错身份和非空payload、重复/在途门禁。
真实三进程再验证双方已提交但一方ACK丢失时无设备推进、无下一轮、没有双确认成功。
保留原数学、材料不复用、未知提交、full字节/哈希/预算/可靠前缀和旧后端强断言。

正式性能测量与软件测试分开，按#120设计预声明同SHA三组light对照各一次；只有生产C及
默认供料短门禁都通过且长期条件合法才10k。首失败保留，不靠重试选择绿色；非默认策略、
有限诊断或1000预送库存不算生产持续资格。完整路线和真实三机另需证据。

#120 S0补货诊断仅在本机cycle/light、默认通信策略、在线16槽、无preload的
`--diagnostic`上下文选择g0..1、165..168、176..180；原full/预送及其他诊断继续原窗口。
单份produce/create、canonical发送/编码和GC记录独立起止，native线程与owner明确；
prepared_step是未来材料步号，control_global_step是INPUT到周期导出回调的公开标签，
不表示CPU正在运行或持有GIL。P1/P2只标最近收到的Client请求步号，Client是否仍在
周期内为未知null。跨窗口GC保留配对/缺端点，不用非CPU差值唯一归因。
发送区间包住原_send_exact（含deadline/系统等待/重新调度），长度仅为公开帧字节；
原meter另含公开计数与注入等待，发送帧计数不能证明失败帧已经完整送达。
每角色仍512槽/72KiB事件编码，总诊断256KiB；运行中无诊断JSON/排序/写盘/主动GC。
仅停止后展开tuple与编码；预算紧张时优先GC、控制/produce/send，随后encode/create等
嵌套细项，报告事件顺序不是时间顺序。overflow/encoded_overflow或缺关键事件均诚实报告。
事前固定一次最多185尝试、首次失败停止，不追加重测；qualification始终false。
诊断保持原材料owner、新鲜性/一次领取、短缺即失败、16槽/8MiB预留、20ms与双ACK。
不改变补货批次/低水位/GC参数，也不新增供料进程或把185步当1000/长期资格。

在项目的 Python 3.11 环境中执行：

| 用途 | 命令 | 未运行内容 |
|---|---|---|
| 快速反馈 | `uv run pytest -m "not integration and not gui and not stress"` | 真实进程/socket/TLS、实际Tk与长时见证 |
| 短进程集成 | `uv run pytest -m "integration and not gui and not stress"` | 实际Tk与stress |
| 短GUI | `uv run pytest -m "gui and not stress"` | stress及其他组 |
| 长时验证 | `uv run pytest -m stress` | 其他三个分区 |
| 当前完整验证 | `uv run pytest` | 无分组排除 |

`integration` 表示实际进程、socket/TLS或间接使用真实网络结果fixture；
`gui` 表示实际Tk；`stress` 表示保留的长轨迹或资源/性能见证。
marker允许重叠，上表按stress、gui、integration、fast的优先级组成互斥分区。
`pyproject.toml` 只启用strict-markers，默认仍收集全部剩余测试。
不使用pytest-xdist，避免端口探测/绑定、Tk和资源测量互相干扰。

#121 的既有动态结果/故障注入集成夹具显式使用非实时诊断调度，保留原来注入位置与
前缀断言，并实际采用新的批量 writer。其 tracemalloc 和故意重启/延迟不是 20 ms 性能
试验。真实周期由可控钟短测试和独立 `benchmark --case cycle` 检查；10k 资格运行不进
默认 pytest，也不能拿短测试通过代替资格通过。

## 保留的关键检查

- 定点正负半舍入、高精度有理数/float、中心化模边界与大整数路径。
- Beaver/Trunc独立公式、公开项归属与材料不能重复使用。
- Protocol 3输出/状态尺度、有限范围、跨会话拒绝和失败时不提交部分状态。
- 明文/安全运行时的整数矩阵小数输入回归、静态与动态控制器、reset和回滚。
- 非线性plant与控制器的独立积分/整数oracle；capture边界、timeout和失败前缀。
- 三角色真实运行、TLS角色/CA、超时/部分启动清理、停止竞争和跨段秘密状态。
- observer结果中数值相等的bool/float身份字段拒绝，保留已有RV-001的19个字段见证。
- 少量GUI mailbox、异步seek、有限窗口及回放中关闭检查。

上述检查是精简后的明确代表，未声称覆盖所有原参数组合。
起摆能量公式采用6组显式角度/模型配对，保留修改惯量/摩擦的一般角代表，
不再运行完整角度×模型笛卡尔积。

## 验证与记录

#120的短回归复用现有scalar/full测试位置：可控钟覆盖采样、材料CPU、设备前、已执行后回调、epoch装配、跨段与最后一步；真实三进程验证v4与原数学重放，并拒绝遗漏失败、假durable、错epoch/步号及bool时间戳。虚拟Clock/I/O预算只验证契约，不能当20ms性能或10k证据。P0两次1500步观察独立于默认pytest，不能在重试中筛选性能结果。

uv run pytest --durations=20 --junitxml="$env:TEMP/pytest-times.xml"
